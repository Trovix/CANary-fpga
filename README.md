# CANary FPGA

Initial receive-only Classical CAN receiver for my dissertation.

## Receiver RTL

The DUT is **`fpga/rtl/can_sniffer.sv`**. Its only inputs are `clk`,
`reset_n` and the logic-level `can_rx` signal from a CAN transceiver.

| File | Responsibility |
| --- | --- |
| `fpga/rtl/can_rx_sync.sv` | Two-register input synchroniser, marked for CDC placement |
| `fpga/rtl/can_bit_timing.sv` | Idle acquisition, SOF synchronisation, sampling and bounded edge resynchronisation |
| `fpga/rtl/can_destuffer.sv` | Remove stuff bits and report stuffing violations |
| `fpga/rtl/can_frame_parser.sv` | Initial standard-frame parser and CRC input stream |
| `fpga/rtl/can_sniffer.sv` | Instantiate and connect the stages |

Default timing is 50 MHz / 1 Mbit/s: `CLKS_PER_BIT=50`,
`SAMPLE_POINT=40` (80%) and `SJW=4` clocks. Parameters use FPGA clocks,
with no generated clocks. At least five clocks after sampling are reserved
for feedback through the receiver pipeline.

The parser handles standard 11-bit data frames with DLC 0..8. It extracts
the identifier, DLC, payload, received CRC and ACK state, then checks the
fixed-form trailer. Payload bytes occupy `[63:56]` first; unused bytes are zero.
Remote frames, extended frames and DLC >8 are rejected as unsupported.
This is not a complete CAN controller or a CAN FD implementation.

`frame_start`, `header_valid`, `frame_complete`, `stuff_error`, `form_error`
and `unsupported_frame` are one-clock events. `frame_complete` occurs at
the end of EOF; intermission handling continues afterwards. Captured fields
remain available until the next SOF. Early header/CRC stream outputs are
provisional and may belong to a frame subsequently rejected.

**CRC calculation and validation are not implemented yet.** `frame_complete`
means the parser reached EOF, not that a frame passed CRC validation.
`crc_data_valid` / `crc_data_bit` expose the destuffed SOF-through-data
stream for the next implementation stage. `received_crc` is captured as sent.
ACK is observed only: this design never drives the bus.

Reset asserts asynchronously. The integrating design must release `reset_n`
synchronously to `clk` and provide appropriate CDC/timing constraints.
Quartus device selection, pin assignments and board implementation are pending.

## Simulation

`fpga/sim/tb_can_stimulus.sv` now instantiates the DUT and checks its outputs
against the transmitted frame, including every bit of the CRC input stream.
The existing `run.ps1` and Questa `run.do` compile the receiver RTL too.

For the cross-platform regression, install Icarus Verilog (`iverilog` and
`vvp` on PATH), then run:

```sh
python fpga/sim/run_tests.py
```

Outputs are written under `fpga/sim/out/` and are not committed.
`tb_can_receiver.sv` replays directed waveforms generated by the Python runner
to exercise corruption, reset, recovery and frame-boundary behaviour.

## Current verification status

This is an initial implementation, pushed before the regression was finished.
Simulation checks have passed for the nominal-rate 2,048-ID sweep, DLC 0..8,
constant/alternating payloads, and individual clock-mismatch runs with a
dominant ACK (990, 995, 1005 and 1010 ns bit periods). Recessive-ACK runs at
995 and 1005 ns also passed. Verilator RTL lint passes without warnings;
an initial generic Yosys synthesis/check reported no problems.

**The complete regression is not passing yet.** Back-to-back recessive-ACK
frames at 990 ns still expose a timing/boundary issue. The directed replay
also currently reports 36/37 completed frames and 7/6 form errors; that case
needs investigation. The script deliberately fails on these discrepancies.
These checks do not establish hardware timing closure or CAN conformance.
